# Security Policy

## Reporting a security concern

Do not publish passwords, customer data, exploitable details, or unpatched vulnerability information in a public issue. Contact the repository owner privately using a communication channel that has been explicitly provided by the project owner.

## Safe handling

- Never commit real passwords, password hashes copied from production, API keys, recovery codes, or authentication tokens.
- Never commit real customer, supplier, employee, or financial records.
- Keep the repository private while reviewing proprietary source and workbook contents.
- Use synthetic test data only after confirming that it does not identify real people or businesses.
- Do not treat worksheet hiding or VBA project protection as encryption or as a secure boundary.
- Review release workbooks and exported source before each distribution.

## Supported versions

Security fixes should be evaluated against versions actively maintained by the project owner. No support period is promised by this file; publish one when a formal policy is adopted.
